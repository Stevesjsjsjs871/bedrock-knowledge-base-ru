# Разбор Add-On: Realistic Biomes 1.3 (для Bedrock 1.26.x)

> **Тип материала:** технический анализ стороннего Add-On по предоставленному архиву.  
> **Заявленная версия:** 1.3.0 в JavaScript-модуле; версия модулей manifest — `[1, 0, 26]`.  
> **Минимальная версия движка:** `1.26.20`.  
> **Автор, указанный в manifest:** Oreville Studios Ltd.  
> **Статус:** статический осмотр ZIP; тестирование в игре не выполнялось.

## Краткий вывод

Архив `Realistic Biomes 1.3 Add-On (1.26.40).mcaddon.zip` содержит связку Behavior Pack (BP) + Resource Pack (RP). BP включает JavaScript Script API, пользовательские блоки, предметы, сущности и рецепты. RP содержит большой набор туманов, частиц, звуков и визуальных ресурсов. Это полезный пример многокомпонентного Add-On, но не исходный код Minecraft и не официальный пакет Mojang.

## Структура и статистика

В архиве обнаружено 1 959 записей, суммарно около 31,8 МБ распакованного содержимого.

### Behavior Pack

- 84 JavaScript-файла в `scripts/oreville_rb/`;
- 35 JSON-файлов в `blocks/`;
- 21 JSON-файл в `items/`;
- 4 JSON-файла в `entities/`;
- 2 файла в `recipes/`;
- manifest, локализация, animation controller и item catalog.

### Resource Pack

- 805 файлов в `fogs/`;
- 447 в `particles/`;
- 317 в `sounds/`;
- 199 в `textures/`;
- 20 в `attachables/`;
- 4 в `entity/` и 4 в `models/`;
- также присутствуют материалы, анимации, render controllers, local lighting, `blocks.json`, `sounds.json` и локализация.

Названия файлов в основном короткие и непрозрачные (например, буквенные идентификаторы), поэтому для полноценного каталога потребуется индексировать JSON-идентификаторы и ссылки между файлами, а не полагаться на имена файлов.

## Наблюдения по Script API

Статический просмотр отдельных файлов показывает импорты `@minecraft/server`, обращения к `world`, игрокам и событиям, использование dynamic properties, команд и звуков, а также перечисления режимов погоды и времени. В коде встречаются внутренние имена и строковые идентификаторы, поэтому семантику многих функций нельзя надёжно восстановить по именам файлов.

В нескольких модулях заметно сильное переименование идентификаторов (обфускация/минификация). Это снижает читаемость, затрудняет аудит и делает рискованным перенос фрагментов кода в собственный проект. Не следует считать выводы о назначении функции доказанными без анализа вызывающих мест и проверки в игре.

Проверяйте Script API не по одной только версии Minecraft, а по совместимости всех используемых методов и событий с целевой версией `@minecraft/server`. Указанная в manifest версия пакета — важная подсказка, но не замена тесту.

## Что проверить в первую очередь

1. **Точка входа и регистрация модулей:** проследить импорт из `qj.js`, порядок инициализации, обработчики событий и script events.
2. **Контракт BP↔RP:** собрать все namespace и identifier из блоков, предметов, сущностей, частиц, звуков, attachables и моделей; выявить отсутствующие ссылки.
3. **JSON-схемы:** проверить `format_version`, обязательные поля и актуальность компонентных схем для Bedrock 1.26.x.
4. **Fog и local lighting:** проверить определения, идентификаторы, переходы и совместимость с графическими режимами.
5. **Производительность:** оценить число частиц, частоту событий и таймеров, объём текстур и звуков, а также поведение при большом числе игроков.
6. **Диагностика:** импортировать BP и RP вместе, проверить Content Log, Script API ошибки и отсутствующие ресурсы.
7. **Графическая совместимость:** отдельно проверить PBR-capability и texture sets; флаг PBR не гарантирует, что все текстуры используют корректные карты.

## Что полезно для базы знаний

Этот кейс подходит для расширения статей о:

- связях manifest и зависимостей BP/RP;
- JavaScript-модулях Script API и точке входа;
- диагностике отсутствующих идентификаторов между BP и RP;
- каталогизации частиц, fog definitions, звуков и визуальных ресурсов;
- аудите сторонних Add-On с обфусцированным кодом;
- проверке PBR и совместимости с конкретной версией Bedrock.

Рекомендуемый следующий артефакт — локальный инструмент-инвентаризатор, который строит CSV/JSON-отчёт по manifest, namespace, identifier и межфайловым ссылкам, не публикуя сами текстуры и звуки.
