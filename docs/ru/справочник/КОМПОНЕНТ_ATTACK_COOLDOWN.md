# Компонент minecraft:attack_cooldown — пауза перед поиском новой цели

`minecraft:attack_cooldown` добавляет сущности период ожидания. Назначение компонента в официальной документации — не позволять сущности пытаться получить новые цели для атаки в течение заданного времени.

**Официальный источник:** [Microsoft Learn — minecraft:attack_cooldown (Stable)](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/entityreference/examples/entitycomponents/minecraftcomponent_attack_cooldown?view=minecraft-bedrock-stable)

## Поля

| Поле | Тип / значение по умолчанию | Назначение |
|---|---|---|
| `attack_cooldown_time` | диапазон чисел с плавающей точкой; не задано | Длительность паузы в секундах. Можно указать одно число либо пару минимального и максимального значений. |
| `attack_cooldown_complete_event` | объект или строка события; не задано | Событие, запускаемое после окончания паузы. Объект может содержать `event` и `target`; также поддерживается простая строка события. |

Поскольку значения по умолчанию не заданы, явно указывайте время и при необходимости событие завершения. Точные детали сверяйте с официальной страницей и форматом вашей версии игры.

## Пример структуры

Пример показывает форму полей, но не является универсальным готовым поведением: строка события должна соответствовать событию, определённому в вашей сущности.

~~~json
{
  "minecraft:attack_cooldown": {
    "attack_cooldown_time": {
      "min": 2.0,
      "max": 3.0
    },
    "attack_cooldown_complete_event": "example:cooldown_finished"
  }
}
~~~

Если используете строковое событие, определите его в соответствующей секции событий Entity JSON. Если у события нет определения, не предполагайте, что движок автоматически создаст его.

## Не путайте три разных механизма

- `minecraft:attack_cooldown` — пауза перед попыткой получить новую цель для атаки.
- Поле `attack_cooldown` в отдельных AI goals — собственный интервал повторного использования конкретной цели поведения; это не тот же самый компонент.
- `minecraft:area_attack.damage_cooldown` — интервал, связанный с нанесением урона по области.

Эти механизмы могут иметь похожие названия, но решают разные задачи. Не переносите поле из одного компонента в другой.

## Проверка

1. Проверьте загрузку сущности в Content Log.
2. Убедитесь, что событие завершения действительно объявлено, если оно используется.
3. Сравните поведение с компонентом и без него при одинаковых AI goals.
4. Повторите тест несколько раз: время может быть задано диапазоном.
5. Если сущность продолжает атаковать текущую цель, не делайте вывод сразу, что компонент не работает: документированное назначение связано с попыткой получить новую цель, а не с универсальной блокировкой любого действия атаки.
