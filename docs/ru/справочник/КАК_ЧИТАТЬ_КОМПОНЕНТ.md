# Как читать документацию компонента сущности

Страница компонента — это не просто пример JSON. Она описывает контракт данных: имя, допустимые поля и контекст использования.

## Проверяйте по порядку
1. **Точное имя** — скопируйте идентификатор без изменения символов.
2. **Назначение** — какую характеристику или часть поведения он задаёт.
3. **Контекст** — в какой секции и для каких сущностей компонент применим.
4. **Поля** — тип каждого значения, обязательность и допустимый диапазон.
5. **Значения по умолчанию** — не предполагайте, что пропущенное поле равно нулю или `false`.
6. **Версия** — ограничения формата, Stable/Preview и эксперименты.
7. **Связи** — зависит ли результат от других компонентов, групп или событий.
8. **Тест** — проверьте минимальный пример и посмотрите Content Log.

## Таблица заметок
| Поле | Что записывать |
|---|---|
| Идентификатор | Точное имя компонента |
| Назначение | Объяснение простым языком |
| Поля | Имя, тип, обязательность, диапазон |
| Значения по умолчанию | Только если указаны источником |
| Версия | Stable/Preview и ограничения |
| Связи | Другие компоненты и события |
| Проверка | Тестовый сценарий и результат |
| Источник | Прямая официальная ссылка и дата проверки |

## Не делайте так
- Не переводите машинные имена компонентов.
- Не выводите тип поля только из примера.
- Не копируйте значения по умолчанию из похожего компонента.
- Не объединяйте похожие имена, пока не сравнили поведение.
- Не называйте компонент «поддерживаемым в Stable», если источник этого не подтверждает.
