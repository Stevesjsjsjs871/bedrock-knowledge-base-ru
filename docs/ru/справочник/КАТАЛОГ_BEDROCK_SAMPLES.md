# Официальные ZIP-архивы Mojang Bedrock Samples

Автоматически обновляемый каталог релизов: [Mojang/bedrock-samples — Releases](https://github.com/Mojang/bedrock-samples/releases).

В релизах Mojang доступны архивы **full** (полные образцы с текстурами, моделями и звуками) и **min** (текстовые файлы, без бинарных ресурсов). Это sample assets для Add-On разработки, а не полный исходный код движка Minecraft. Описание upstream: [README](https://github.com/Mojang/bedrock-samples#readme).

Полный список тегов, даты публикации и прямые ссылки на ZIP хранятся в [каталоге по версиям](КАТАЛОГ_BEDROCK_SAMPLES_ПО_ВЕРСИЯМ.md) и машиночитаемом [JSON-индексе](../../../data/bedrock_samples_releases.json). Индекс обновляется GitHub Actions по расписанию и вручную.

## Как использовать архивы в базе знаний

1. Для сравнения JSON, схем и конфигураций сначала загружайте min.
2. Для проверки текстур, моделей, звуков и других бинарных ресурсов используйте full.
3. Сравнивайте конкретные теги релизов, а не только major/minor версии.
4. Сохраняйте путь файла, diff, тег обеих версий, changelog и вывод теста.
5. Не считайте пример из sample pack гарантией поддержки конкретного поля или графического эффекта — сверяйте официальную документацию и проверяйте в целевой игре.

## Почему ZIP не хранятся в этом репозитории

Полные архивы могут быть большими, часто обновляются и принадлежат upstream-проекту. Поэтому здесь сохраняются метаданные, прямые ссылки и инструменты анализа; архив скачивается с GitHub Mojang по необходимости. Перед копированием ресурсов проверяйте [лицензию Mojang samples](https://github.com/Mojang/bedrock-samples/blob/main/LICENSE.md).

## Проверка охвата

Индекс включает опубликованные релизы, доступные через GitHub Releases API на момент последнего обновления. Он не гарантирует, что каждый исторический билд Bedrock когда-либо существовавший выпускался в виде отдельного sample ZIP.
