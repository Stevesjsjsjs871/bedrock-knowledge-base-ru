# Компонент minecraft:type_family

Компонент относит сущность к одной или нескольким логическим семьям. Семейства используются фильтрами и другими системами игры для группировки сущностей. Например, моб может принадлежать к семействам mob, monster и undead.

Источник: [официальная страница minecraft:type_family](https://github.com/MicrosoftDocs/minecraft-creator/blob/main/creator/Reference/Content/EntityReference/Examples/EntityComponents/minecraftComponent_type_family.md).

## Поля

| Поле | Тип | Назначение |
|---|---|---|
| family | массив строк | Набор семей, к которым относится сущность. |

## Пример

~~~json
{
  "minecraft:type_family": {
    "family": [
      "custom_creature",
      "mob",
      "monster"
    ]
  }
}
~~~

Строки семейства — категории, а не идентификатор сущности. Идентификатор, например example:crystal_beast, задаётся отдельно.

## Семейство, тег и идентификатор — разные вещи

- **Identifier** — уникальное имя типа сущности.
- **Family** — категория для фильтров и игровой логики.
- **Tag** — отдельная метка, используемая соответствующими механизмами.

Если фильтр проверяет семью, наличие похожей строки в идентификаторе не делает условие истинным. Семейство нужно явно указать в minecraft:type_family.

## Пример фильтра

~~~json
{
  "test": "is_family",
  "subject": "other",
  "value": "monster"
}
~~~

Это иллюстрация условия фильтра, а не самостоятельная полная конфигурация компонента. Значение subject зависит от контекста конкретного фильтра.

## Типичные ошибки

- Считать, что семейство автоматически создаётся из идентификатора сущности.
- Использовать семейство как замену тегу или уникальному идентификатору.
- Указать неверный subject в фильтре.
- Не учитывать, что широкая категория вроде monster может влиять на большее число сущностей, чем ожидалось.

**Статус:** черновик; основной формат сверен с официальной страницей, игровые сценарии не заявлены как протестированные.
