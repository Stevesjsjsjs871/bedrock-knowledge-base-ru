# Компонент minecraft:damage_sensor — реакция на полученный урон

`minecraft:damage_sensor` задаёт правила обработки входящего урона: какие условия проверять, какой урон отменять или изменять и какие события вызывать при выполнении условий.

**Официальный источник:** [Microsoft Learn — minecraft:damage_sensor (Stable)](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/entityreference/examples/entitycomponents/minecraftcomponent_damage_sensor?view=minecraft-bedrock-stable)

## Основные поля

| Поле | Тип / значение по умолчанию | Назначение |
|---|---|---|
| `deals_damage` | выбор режима; по умолчанию `false` | Определяет, будет ли полученный урон применён к сущности. |
| `triggers` | объект или список триггеров; не задан | Правила для конкретных причин урона, фильтров и событий. |

Внутри `triggers` официальная документация описывает, в частности:

- `cause` — причина урона, которая активирует правило;
- `damage_modifier` — прибавка или вычитание из базового урона;
- `damage_multiplier` — множитель базового урона;
- `deals_damage` — применять ли полученный урон;
- `event` — событие, вызываемое при выполнении условия;
- `filters` — условия применимости правила;
- `on_damage` — определение сущностей и события, связанные с попаданием;
- `on_damage_sound_event` — звук, который проигрывается при выполнении фильтров `on_damage`.

## Режимы deals_damage

| Значение | Смысл |
|---|---|
| `yes` | Полученный урон применяется. |
| `no` | Полученный урон не применяется. |
| `no_but_side_effects_apply` | Урон не применяется, но побочные эффекты атаки сохраняются, например потеря прочности оружия и эффекты зачарований. |
| `no_but_entity_effects_apply` | Урон не применяется, но сохраняются отбрасывание и эффекты зачарований; оружие атакующего используется как обычно, а сущность не мигает красным. |

Проверяйте написание значений и структуру триггеров по официальной странице: это не обычное булево поле во всех вариантах, некоторые режимы являются строковыми значениями.

## Пример: отменить урон от падения

~~~json
{
  "minecraft:damage_sensor": {
    "triggers": {
      "cause": "fall",
      "deals_damage": "no"
    }
  }
}
~~~

Это соответствует форме примера Bat в официальной документации. Прежде чем использовать, проверьте, не требуется ли вашей сущности дополнительная логика или другие триггеры.

## Пример: не получать урон от владельца

Официальный пример Allay использует фильтр внутри `on_damage`, который проверяет, что атакующий относится к семье `player` и является владельцем. Такой вариант полезнее, чем безусловно игнорировать урон от всех игроков.

## Отличия от похожих компонентов

- `minecraft:damage_sensor` реагирует на урон, который получает сущность.
- `minecraft:attack` описывает обычную атаку ближнего боя самой сущности.
- `minecraft:area_attack` наносит урон другим сущностям в пределах области.
- `minecraft:hurt_on_condition` наносит урон самой сущности, когда выполнены условия среды или фильтра.

## Диагностика

1. Начните с одного триггера и одной причины урона.
2. Уточните, должен ли урон отменяться полностью или нужно сохранить побочные эффекты.
3. Если используется `on_damage`, проверьте субъект фильтра: `other`, `damager` и `self` не взаимозаменяемы.
4. Проверьте объявленное событие и его точное имя.
5. Проверяйте отдельно каждую причину урона: падение, снаряд и ближняя атака — разные случаи.
6. После изменения компонента изучите Content Log и повторите тест в чистом мире.

**Статус:** описание основано на официальной документации Stable; тестирование в игре не заявляется.
