# Таблицы лута: pools, entries, conditions и functions

**Статус:** editorial-explanation · проверяйте схему конкретной таблицы в актуальной документации Stable.

Эта статья расширяет [обзор таблиц лута](ТАБЛИЦЫ_ЛУТА_ОБЗОР.md): объясняет пулы, записи, условия и функции, а также способы тестирования вероятностных результатов.

## Где хранится таблица

Таблицы лута располагаются в Behavior Pack внутри папки loot_tables/. Подпапки помогают организовать проект, например entities/, blocks/ или chests/, но файл должен быть указан в компоненте или механизме, который его использует.

Не путайте таблицу лута, правило появления и рецепт: они решают разные задачи.

## Основные части

| Поле | Роль |
|---|---|
| pools | Список независимых пулов розыгрыша. |
| rolls | Количество попыток выбрать запись в пуле; формат значения проверяйте по схеме. |
| entries | Список возможных результатов пула. |
| type | Тип записи, например предмет, вложенная таблица или пустой результат, если это поддерживается схемой. |
| name | Идентификатор предмета или другого ресурса для соответствующего типа записи. |
| weight | Относительный вес выбора, если используется взвешенный выбор. |
| conditions | Условия, при которых запись или пул участвует в расчёте. |
| functions | Преобразования результата, поддерживаемые конкретным типом таблицы. |

Это словарь понятий, а не полная JSON Schema. Проверяйте допустимые поля для конкретной версии и типа лута.

## Минимальный учебный пример

Фрагмент иллюстрирует таблицу с одним пулом и одной записью. Перед запуском сверьте его с текущей схемой и убедитесь, что предмет существует.

~~~json
{
  "pools": [
    {
      "rolls": 1,
      "entries": [
        {
          "type": "item",
          "name": "minecraft:diamond"
        }
      ]
    }
  ]
}
~~~

Один пул делает одну попытку и содержит одну запись предмета. Пример не включает случайность, условия или функции: сначала проверьте базовый сценарий, затем усложняйте его.

## Вероятность и вес

Вес — относительная величина, а не процент. Если в одном пуле есть две записи с весами 1 и 3, и обе всегда допустимы, то при обычном взвешенном выборе вторая запись получает три доли из четырёх. Это объяснение предполагает, что нет дополнительных условий или особенностей, влияющих на результат.

Если запись отфильтрована условием, не рассчитывайте вероятность так, будто она всё ещё участвует. Проверяйте условия отдельно.

## Conditions и functions — не одно и то же

- **Condition** отвечает на вопрос: может ли пул или запись участвовать при текущих обстоятельствах?
- **Function** изменяет сформированный результат, например количество или свойства предмета, если функция поддерживается схемой.

Не копируйте функцию из таблицы одного типа в другую без проверки: поддерживаемые функции и контекст могут отличаться.

## Как проектировать сложную таблицу

1. Опишите ожидаемый результат словами: что, когда и при каком событии выпадает.
2. Сделайте одну запись без условий.
3. Проверьте путь и ссылку на таблицу из компонента, блока или сущности.
4. Добавьте дополнительные записи.
5. Добавьте веса и рассчитайте ожидаемое распределение.
6. Добавьте одно условие и проверьте оба исхода.
7. Добавляйте функции по одной.
8. Повторяйте тест, если используется случайность.
9. Проверяйте Content Log и точные идентификаторы.

## Диагностика

| Симптом | Что проверить |
|---|---|
| Ничего не выпадает | Вызывается ли таблица, верен ли путь, есть ли допустимые записи. |
| Выпадает не тот предмет | name, тип записи и условия. |
| Вероятности выглядят неверно | Какие записи участвуют, каковы веса и сколько раз бросается пул. |
| Количество предметов отличается от ожидания | Функции результата и ограничения стека. |
| Ошибка только в одном типе лута | Совместимость таблицы с контекстом, который её вызывает. |
