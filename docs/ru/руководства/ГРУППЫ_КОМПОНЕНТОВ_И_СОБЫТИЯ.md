# Группы компонентов и события сущностей

> Статус: учебное объяснение Stable. Проверяйте точные поля и доступные события в документации целевой версии.

## Зачем нужны component groups

Компоненты задают свойства и возможности сущности. Группы компонентов (`component_groups`) позволяют объединить набор компонентов под именем и добавлять или удалять его при изменении состояния сущности.

Это удобно для состояний вроде «детёныш/взрослый», «обычный/усиленный» или «подготовка/атака». Вместо того чтобы описывать каждое состояние как отдельную сущность, можно переключать наборы компонентов.

## Как работают события

Событие в JSON сущности описывает изменения, которые нужно применить, например добавить или удалить группы компонентов. События могут вызываться компонентами, другими событиями, анимациями поведения, командами и некоторыми игровыми механизмами.

Упрощённая схема:

1. Происходит условие или действие.
2. Вызывается именованное событие.
3. Событие добавляет и/или удаляет группы компонентов.
4. Сущность продолжает работать с изменённым набором компонентов.

Официальное руководство: [Entity Events](https://learn.microsoft.com/en-us/minecraft/creator/documents/entityevents?view=minecraft-bedrock-stable).

## Условный пример структуры

Это иллюстрация структуры, а не готовая сущность: состав компонентов и формат события необходимо проверить для вашей задачи.

```json
{
  "component_groups": {
    "sample:powered_state": {
      "minecraft:movement": {
        "value": 0.35
      }
    }
  },
  "events": {
    "sample:enable_power": {
      "add": {
        "component_groups": [
          "sample:powered_state"
        ]
      }
    },
    "sample:disable_power": {
      "remove": {
        "component_groups": [
          "sample:powered_state"
        ]
      }
    }
  }
}
```

В примере группа добавляет компонент движения с другим значением. Для реального проекта проверьте, допустим ли такой компонент и как он взаимодействует с уже активными компонентами сущности.

## Порядок выполнения и проектирование

Не предполагайте, что два события, пришедшие в один игровой тик, обязательно увидят результаты друг друга немедленно. Некоторые изменения рассчитываются и применяются на стороне сущности позднее в цикле обновления.

Практические правила:

- Давайте событиям имена по действию или переходу состояния.
- Группируйте компоненты по логическому состоянию, а не по случайным признакам.
- Избегайте ситуации, когда несколько групп одновременно задают несовместимые значения одного свойства.
- Проверяйте все пути входа в состояние и выхода из него.
- Проверяйте создание сущности через яйцо призыва, разведение, превращение и команду `/summon`: стартовые события могут отличаться.
- Используйте Content Log для диагностики неверных имён, структуры JSON и неподдерживаемых полей.

## События появления

Не путайте событие, запускаемое при обычном появлении, с любым возможным способом создания сущности. В зависимости от источника появления могут вызываться разные события. Если поведение при призыве отличается от поведения при естественном появлении, сначала проверьте сценарий создания и событие, которое он запускает.
