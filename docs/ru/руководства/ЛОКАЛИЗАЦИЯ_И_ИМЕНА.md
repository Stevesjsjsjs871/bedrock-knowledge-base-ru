# Локализация и отображаемые имена

> Статус: обзор организации языковых строк. Конкретные ключи и требования проверяйте в документации соответствующего типа контента.

## Зачем нужна локализация

Внутренние идентификаторы используются JSON и игровыми системами, а отображаемые названия предназначены для игрока. Не подменяйте одно другим: переводить нужно текст, который видит пользователь, но не технические ключи, имена API или идентификаторы компонентов.

## Общий принцип

1. Определите ключ локализации, который ожидает конкретный тип контента.
2. Добавьте значение ключа в нужный языковой файл.
3. Проверьте, что файл находится в правильной папке пакета.
4. Убедитесь, что имя ключа совпадает в определении контента и файле языка.
5. Проверьте результат в игре с нужным языком интерфейса.

Формат локализации зависит от контента и текущей схемы. Не предполагайте, что все типы файлов используют один и тот же способ объявления отображаемого имени.

## Рекомендации по ключам

- Используйте последовательную схему именования.
- Не используйте один и тот же ключ для несвязанных элементов, если это затрудняет перевод.
- Сохраняйте уникальность имён в пределах проекта.
- Добавляйте переводы только для языков, которые проект действительно поддерживает.
- Не помещайте технические комментарии в строку, которую увидит игрок.
- Проверяйте кодировку файлов и специальные символы.

## Проверка

Если вместо переведённого имени отображается ключ:
- проверьте написание ключа;
- проверьте наличие записи в языковом файле;
- проверьте путь и имя файла;
- убедитесь, что язык включён/поддерживается;
- проверьте, что другой активный пакет не переопределяет соответствующие ресурсы.
