# Render Controllers: подробный справочник

**Статус:** editorial-explanation; сверяйте формат и доступность полей с документацией Stable для целевой версии игры.

Render Controller — это правило клиентской отрисовки. Он выбирает, какую геометрию, материал, текстуру и какие кости показывать. Он не заменяет серверное поведение сущности и сам по себе не создаёт игровые события.

## Где находится в системе

1. Модель описывает кости и геометрию.
2. Текстуры задают изображения поверх модели.
3. Материалы определяют способ отрисовки.
4. Client Entity связывает ресурсы с сущностью.
5. Render Controller задаёт правила выбора ресурсов и видимости частей модели.

Обычно файл находится в корне Resource Pack в каталоге render_controllers. Точное расположение и допустимый формат проверяйте по официальному справочнику.

## Минимальная схема связей

В client entity объявляется короткое имя контроллера в массиве render_controllers. Это имя должно совпасть с ключом контроллера в JSON-файле. Отдельно в description задаются словари geometry, textures и materials, связывающие короткие ключи с полными идентификаторами ресурсов.

Пример связей, не полный файл для копирования:

~~~json
{
  "minecraft:client_entity": {
    "description": {
      "geometry": { "default": "geometry.example" },
      "textures": { "default": "textures/entity/example" },
      "materials": { "default": "entity_alphatest" },
      "render_controllers": [ "controller.render.example" ]
    }
  }
}
~~~

Контроллер должен ссылаться на те ключи, которые действительно объявлены в client entity. Названия ключей вроде default — это локальные имена связей, а не универсальные зарезервированные значения.

## Основные части контроллера

- **geometry** — ключ геометрии, которую нужно отрисовать.
- **materials** — набор назначений материалов по костям или группам костей.
- **textures** — одна или несколько текстурных привязок.
- **arrays** — индексируемые наборы вариантов. Они полезны, когда внешний вид выбирается по Molang-выражению.
- **part_visibility** — правила скрытия и показа частей модели.

Не копируйте эти поля вслепую между примерами: набор поддерживаемых возможностей зависит от формата и конкретной схемы. Сверяйте каждое поле с [официальным справочником Render Controllers](https://learn.microsoft.com/en-us/minecraft/creator/documents/animations/animationrendercontroller?view=minecraft-bedrock-stable).

## Когда нужны массивы

Массивы помогают переключать варианты без дублирования всей сущности. Например, можно хранить несколько текстур и выбирать индекс по пользовательскому свойству или Molang-условию. При этом выражение должно возвращать допустимый индекс, а сам массив — существовать и содержать нужный элемент.

Перед использованием проверьте:
- совпадает ли имя массива во всех местах;
- существует ли массив с нужным типом данных;
- не выходит ли вычисленный индекс за пределы;
- доступно ли выбранное Molang-выражение в контексте отрисовки;
- не предполагает ли пример Preview-возможность.

## Диагностика невидимой или неверно окрашенной модели

Проверяйте цепочку в таком порядке:

1. У активного Resource Pack правильная структура каталогов.
2. Идентификатор client entity совпадает с ожидаемым.
3. Имя render controller в client entity совпадает с ключом в файле.
4. Ключи geometry, textures и materials объявлены и написаны одинаково.
5. Файл геометрии существует, а названия костей в part_visibility и materials совпадают с моделью.
6. Пути текстур указаны без расширения там, где формат ожидает именно такой путь.
7. Molang-выражения возвращают корректные значения.
8. Content Log не сообщает об ошибке разбора JSON или отсутствующем ресурсе.

Если модель видна, но части пропадают, временно уберите условную видимость и верните базовую геометрию и текстуру. Затем возвращайте по одному правилу.

## Типичные ошибки

| Ошибка | Почему возникает | Что проверить |
|---|---|---|
| Контроллер не найден | Имя в client entity не совпадает с ключом | Идентификатор и путь файла |
| Модель невидима | Неверная геометрия или все кости скрыты | Geometry key и part_visibility |
| Текстура не применяется | Не совпадают ключи или путь | Словарь textures и массивы |
| Вариант не переключается | Условие всегда возвращает одно значение | Контекст Molang, тип и диапазон индекса |
| На одной версии работает, на другой нет | Использовано неподдерживаемое поле | Формат и минимальная версия движка |
