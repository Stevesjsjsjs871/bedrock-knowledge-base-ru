# Script API: обзор и выбор правильного инструмента

> Статус: обзорная статья. Script API развивается; конкретные модули, события и сигнатуры нужно проверять по документации для целевой версии.

## Что такое Script API

Script API позволяет писать код на JavaScript/TypeScript для взаимодействия с игровым миром через поддерживаемые модули Minecraft. Это другой уровень возможностей по сравнению с декларативными JSON-файлами: скрипт может реагировать на события, читать и изменять доступные данные мира и координировать игровую логику в рамках разрешённого API.

Официальная документация:
- [Minecraft Creator documentation](https://learn.microsoft.com/en-us/minecraft/creator/)
- [MicrosoftDocs/minecraft-creator](https://github.com/MicrosoftDocs/minecraft-creator)

## Когда использовать JSON, Molang или Script API

| Задача | С чего начать |
|---|---|
| Задать стандартные свойства сущности | Компоненты сущности в BP |
| Переключать наборы компонентов по событию | Events и component groups |
| Вычислить небольшое значение в поддерживаемом поле JSON | Molang |
| Управлять последовательностью сложной логики, которую предоставляет API | Script API |
| Изменить текстуру, геометрию или визуальную анимацию | Resource Pack и визуальные системы |

Это ориентир, а не жёсткое ограничение: некоторые задачи можно решать несколькими способами. Выбирайте наименее сложный инструмент, который удовлетворяет требованиям и поддерживается целевой версией.

## Основные части скриптового пакета

В проектах со скриптами обычно требуется:
- Behavior Pack с манифестом и модулем типа script;
- входной файл скрипта;
- корректно объявленные зависимости на нужные модули API;
- версия API, совместимая с целевой версией игры;
- настройка мира, необходимая для используемых возможностей.

Точные поля манифеста и импортируемые модули проверяйте в актуальном официальном руководстве. Не копируйте старый манифест из случайного примера без проверки версий.

## Практический рабочий цикл

1. Выберите одну задачу, которую должен решать скрипт.
2. Найдите соответствующий класс, событие или метод в актуальной справке.
3. Проверьте, относится ли API к Stable или Preview.
4. Объявите нужные модули и зависимости.
5. Реализуйте минимальный сценарий.
6. Запустите его в тестовом мире и проверьте ошибки загрузки и выполнения.
7. Увеличивайте сложность небольшими шагами.

## Частые причины проблем

- Версия зависимости API не соответствует доступной версии игры.
- Импортируется модуль или символ, отсутствующий в выбранной версии.
- Используется пример из Preview как будто он Stable.
- Скрипт запускается не в том пакете или его входной файл не указан в манифесте.
- Логика предполагает, что событие срабатывает ровно один раз, хотя документация этого не гарантирует.
- Код не обрабатывает ситуацию, когда объект или компонент недоступен.

## Правило документации

Для каждой страницы Script API указывайте имя модуля, статус Stable/Preview, версию документации и ссылку на официальный источник. Не переписывайте сигнатуры по памяти: даже небольшое изменение типа параметра может сделать пример нерабочим.
