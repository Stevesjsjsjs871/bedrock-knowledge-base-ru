# Рецепты JSON: типы, ингредиенты и проверка

**Статус:** editorial-explanation · допустимые поля зависят от типа рецепта и версии Minecraft.

Рецепты в Behavior Pack описывают преобразование входных предметов в результат. Они не создают предмет сами по себе: определение предмета, его отображение и рецепт — разные части Add-On.

Официальные источники:
- [Introduction to Recipes](https://learn.microsoft.com/en-us/minecraft/creator/documents/recipeintroduction?view=minecraft-bedrock-stable)
- [Recipe JSON Reference](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/recipereference/?view=minecraft-bedrock-stable)
- [Comprehensive Add-On Pack Contents](https://learn.microsoft.com/en-us/minecraft/creator/documents/comprehensivepackcontents?view=minecraft-bedrock-stable)

## Где хранить файлы

Файлы рецептов обычно располагаются в папке recipes/ Behavior Pack. Имя файла может быть понятным и произвольным, но рецепт должен содержать корректное описание, а пакет — быть активирован в мире.

## Типы рецептов

| Тип | Когда применяется |
|---|---|
| Shaped crafting | Рецепт верстака, где расположение ингредиентов имеет значение. |
| Shapeless crafting | Рецепт верстака, где важен набор ингредиентов, а не расположение. |
| Furnace и родственные типы | Преобразование предмета через соответствующий блок обработки. |
| Brewing и другие специализированные типы | Только в поддерживаемых игровых механизмах и форматах. |

Это ориентир по категориям. Точные идентификаторы type и допустимые поля берите из Recipe JSON Reference для целевой версии.

## Общие части рецепта

В зависимости от типа определение может включать:
- format_version — версию формата JSON;
- корневой тип рецепта, например minecraft:recipe_shaped или minecraft:recipe_shapeless;
- description с идентификатором рецепта;
- tags — места или категории использования рецепта;
- ingredients либо key и pattern — входные материалы;
- result — предмет и количество результата.

Не каждый тип использует все эти поля. Не вставляйте все поля в каждый рецепт по аналогии.

## Shaped и shapeless — разные модели

**Shaped** связывает символы шаблона с ингредиентами. Ошибка в строках шаблона, ключах или пробелах может изменить рецепт или сделать его недействительным.

**Shapeless** описывает набор ингредиентов без фиксированной формы. Если важно точное количество каждого материала, проверьте поддерживаемую структуру ингредиентов и формат количества.

## Идентификаторы и namespace

Используйте полные идентификаторы предметов, например minecraft:stick для ванильного предмета или sample:crystal для пользовательского. Пользовательский ID должен совпадать с определением предмета. Сходство отображаемых названий ничего не гарантирует: рецепт работает с идентификаторами, а не с текстом локализации.

## Теги рецепта

Теги указывают, где рецепт может использоваться, например в определённом интерфейсе или механизме обработки. Неверный тег — частая причина, почему JSON загружается, но рецепт не появляется там, где ожидается.

Не угадывайте строку тега. Сверяйте её с актуальной документацией и примером именно для выбранного типа рецепта.

## Практический порядок разработки

1. Убедитесь, что входные предметы существуют.
2. Создайте минимальный рецепт одного типа.
3. Проверьте корневой тип и format_version.
4. Проверьте description.identifier и отсутствие конфликтов ID.
5. Сверьте теги и формат ингредиентов.
6. Проверьте предмет и количество результата.
7. Запустите мир с активным Behavior Pack.
8. Найдите рецепт в ожидаемом интерфейсе и проверьте крафт.
9. Только после успеха добавляйте сложные ингредиенты или дополнительные параметры.

## Диагностика

| Симптом | Вероятная причина |
|---|---|
| Рецепт не появляется | Неверный тег, тип рецепта, ID, версия формата или пакет не активирован. |
| Один ингредиент не распознаётся | Ошибка namespace/ID или предмет не определён. |
| Shaped-рецепт работает иначе | Ошибка в pattern, символах или key. |
| Результат неверный | Неверный ID результата или количество. |
| JSON не загружается | Синтаксис или поля не соответствуют схеме типа. |

## Рецепт, лут и появление

- Рецепт превращает входные предметы в результат.
- Таблица лута выбирает возможные результаты для события добычи или другого поддерживаемого сценария.
- Spawn rules управляют условиями естественного появления сущности.

Если предмет не выпадает с моба, изменение рецепта не решит проблему. Если предмет нельзя скрафтить, проверяйте файл рецепта и его теги, а не таблицу лута.
