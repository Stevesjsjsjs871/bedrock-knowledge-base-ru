# Behavior Pack и Resource Pack: в чём разница

## Простое объяснение
**Behavior Pack (BP)** отвечает за игровые данные и логику. **Resource Pack (RP)** отвечает за то, как содержимое выглядит и звучит. Для некоторых видов контента нужны оба пакета; конкретные требования зависят от типа ресурса.

## Типичные обязанности
| Задача | Обычно находится в |
|---|---|
| Поведение и компоненты сущности | BP |
| Правила появления сущности | BP |
| Рецепты и часть игровых определений | BP |
| Скрипты игрового поведения | BP, если используется соответствующая API-система |
| Текстуры и геометрия модели | RP |
| Клиентское определение сущности | RP |
| Анимации и render controllers | RP |
| Локализационные строки | Зависит от используемого формата и назначения |

Таблица показывает типичное распределение, а не исчерпывающий список всех форматов.

## Как пакеты связаны
1. Каждый пакет имеет собственный манифест.
2. У каждого пакета и модуля, где это требуется схемой, должны быть корректные UUID и версии.
3. Зависимости связываются по идентификатору пакета и версии.
4. В тестовом мире включайте все нужные пакеты.
5. Если поведение работает, а модель отсутствует, сначала проверяйте RP, идентификатор сущности, пути к ресурсам и Content Log.

## Частая ошибка
Поместить файл в правильный по смыслу пакет недостаточно: он также должен иметь правильный формат, имя, путь и ссылки на другие ресурсы.
