# Пользовательские блоки: основы

> Статус: вводное руководство. Поля определения блока и доступность возможностей нужно сверять с актуальной Block Reference для целевой версии.

## Из чего состоит пользовательский блок

Разработка пользовательского блока обычно затрагивает несколько слоёв:

- определение блока и его поведения/свойств в Behavior Pack;
- текстуру и регистрацию текстуры в Resource Pack;
- отображаемое имя, если оно требуется;
- состояния блока и permutations, если блок должен иметь несколько вариантов;
- дополнительные механики, если они поддерживаются схемой и нужны проекту.

Не каждый блок требует сложной геометрии или нескольких состояний. Начните с минимального определения.

## Состояния и permutations

Состояния блока позволяют хранить варианты блока в предусмотренных системой значениях. Permutations позволяют выбирать набор поддерживаемых компонентов в зависимости от состояния или условия. Это помогает моделировать переключаемые варианты без создания отдельного идентификатора для каждого внешнего состояния.

Пример концепции: блок может иметь состояние sample:active, а условие для permutation определяет, какой компонент включить при активном значении. Это лишь схема идеи — точные имена полей, типы состояний и допустимые компоненты нужно взять из актуальной справки.

## Порядок разработки

1. Выберите уникальный идентификатор блока с собственным namespace.
2. Создайте минимальное определение в BP.
3. Подключите текстуру по актуальной схеме RP.
4. Проверьте, что блок загружается и отображается.
5. Добавьте состояния, если они действительно нужны.
6. Добавьте permutations по одному условию за раз.
7. Проверьте размещение, разрушение, дропы и взаимодействие в тестовом мире.

## Отладка

- Проверьте синтаксис JSON и правильный путь.
- Сверьте ID текстуры с записью в атласе.
- Убедитесь, что состояние объявлено и используется с тем же именем.
- Проверьте типы значений: строка, число и boolean не взаимозаменяемы.
- Не используйте свойства из документации Preview в Stable без явной проверки.
- Просмотрите Content Log.
