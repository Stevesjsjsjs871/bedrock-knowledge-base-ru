# Как вносить изменения в базу знаний

Цель проекта — сделать русскоязычную карту Minecraft Bedrock Add-Ons, которая объясняет материал и не теряет связь с официальной и community-документацией.

## Перед добавлением статьи

1. Найдите тему в [карте знаний](../КАРТА_ЗНАНИЙ.md).
2. Проверьте [каталог исходных страниц](../КАТАЛОГ_СТАТЕЙ.md).
3. Изучите [кандидатов на дубли](../ПОВТОРЫ_И_СВЯЗИ.md).
4. Проверьте официальную справку и практические руководства.
5. Определите, относится ли тема к Stable, Preview или к общественному руководству.

## Требования к статье

Статья должна:
- начинаться с понятного объяснения задачи;
- сохранять технические имена API, JSON-ключи и идентификаторы без перевода;
- различать подтверждённые сведения и непроверенные предположения;
- содержать ссылки на первоисточники;
- объяснять типичные ошибки и способ проверки;
- ссылаться на соседние темы вместо дублирования больших фрагментов;
- не заявлять, что пример протестирован, если теста не было.

Используйте [шаблон статьи](../справочник/ШАБЛОН_СТАТЬИ.md) и [правила проверки примеров](ПРАВИЛА_ПРОВЕРКИ_ПРИМЕРОВ.md).

## Как объединять повторяющиеся страницы

Не объединяйте страницы только потому, что заголовки совпадают. Сравните назначение, версию, поля, примеры и исключения. Если один источник описывает дополнительное ограничение, сохраните его в итоговой статье. Все исходные ссылки должны остаться.

## Перед завершением изменения

- [ ] Все относительные Markdown-ссылки ведут к существующим файлам.
- [ ] В статье нет неотмеченных предположений.
- [ ] Указан правильный статус Stable/Preview.
- [ ] Примеры JSON/Molang/Script API сверены с целевой версией.
- [ ] Лицензии и атрибуция проверены.
- [ ] Карта знаний и README обновлены, если добавлена новая основная тема.

## Автоматическая каталогизация

Workflow GitHub Actions синхронизирует исходные репозитории и обновляет каталог. Он не переводит статьи автоматически и не выполняет смысловое слияние. Машинные совпадения — это очередь на редакционную проверку, а не готовое решение.
