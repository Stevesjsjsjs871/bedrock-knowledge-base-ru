# Molang: переменные, контексты и query

**Статус:** editorial-explanation · примеры синтаксиса сверяйте с контекстом, в котором выражение выполняется.

Эта статья дополняет [основы Molang](MOLANG_ОСНОВЫ.md) и объясняет, чем отличаются запросы к состоянию игры, временные значения, переменные сущности и контекстные значения. Выражение может быть синтаксически правильным, но использовать данные, недоступные в конкретном месте JSON.

## Первое правило: контекст важнее названия query

Molang — выражения, встроенные в систему данных Minecraft. Это не полноценный JavaScript, и доступные данные различаются между файлами. Выражение для клиентской анимации, условие permutation блока и выражение в событии сущности могут иметь разные ограничения.

Перед использованием query выясните:
1. В каком поле JSON находится выражение.
2. Выполняется ли оно в Resource Pack или Behavior Pack.
3. Относится ли оно к сущности, блоку, предмету или другому объекту.
4. Какой тип результата ожидает поле.
5. Есть ли у query ограничения по версии или статусу Preview.

## Четыре основных пространства имён

| Запись | Для чего используется | Важное ограничение |
|---|---|---|
| **query.*** или **q.*** | Чтение игровых данных через query-функции | Не каждая query доступна во всех контекстах. |
| **temp.*** или **t.*** | Временные промежуточные вычисления | Не используйте как долговременное состояние. |
| **variable.*** или **v.*** | Переменные, хранящиеся на сущности в поддерживаемом Molang-контексте | Не следует считать постоянным сохранённым хранилищем. |
| **context.*** или **c.*** | Значения, предоставляемые Minecraft для конкретного контекста | Обычно доступны только для чтения и лишь там, где определён контекст. |

Короткие формы — алиасы соответствующих пространств имён. В обучающих примерах полные имена обычно легче читать.

## Query без аргументов и с аргументами

Если query не требует аргументов, синтаксис обычно выглядит так:

~~~molang
query.is_baby
~~~

Если нужны аргументы, передавайте их в круглых скобках:

~~~molang
query.property('example:mode')
~~~

Не добавляйте скобки и аргументы наугад: сверяйте точную сигнатуру в справочнике. Там могут быть указаны обязательные аргументы, возвращаемый тип, версия, контекст и ограничения.

## Пример вычисления в несколько шагов

~~~molang
temp.wave = math.sin(query.anim_time * 1.2);
return temp.wave * temp.wave;
~~~

Выражение вычисляет промежуточное значение, сохраняет его во временной переменной и возвращает итог. В многооператорном выражении используйте return, когда нужно явно вернуть результат. Не переносите этот пример в поле с другим ожидаемым типом или контекстом без проверки требований поля.

## Значения по умолчанию и отсутствующие данные

Оператор null-coalescing, записываемый как **??**, позволяет подставить резервное значение, если переменная или ссылка не может быть разрешена:

~~~molang
variable.speed = (variable.saved_speed ?? 1.0);
~~~

Это иллюстрирует синтаксис резервного значения, но не заменяет проверку конкретного поля. Оператор не делает недействительную геометрию, текстуру или материал существующими ресурсами. Если выражение ссылается на отсутствующий ресурс, исправляйте ссылку и регистрацию ресурса.

## Molang variable не равно Entity Property

Эти механизмы не следует путать:

- **Molang variable** (variable.*) — значение в системе выражений Molang, связанное с сущностью в поддерживаемом контексте. Не следует считать его сохранённым после выхода и повторной загрузки.
- **Entity Property** — объявленное свойство сущности в Behavior Pack. Оно имеет определённый тип и диапазон и может читаться через поддерживаемые query, например query.property.
- **Переменная Script API** — состояние, которым управляет JavaScript/TypeScript-код. Для неё действуют правила Script API, а не синтаксис Molang.

Если состояние должно быть частью определения сущности и участвовать в фильтрах или событиях, рассмотрите Entity Properties. Для вычисления визуального эффекта или анимации может подойти Molang. Для сложной игровой логики сравните с [обзором Script API](SCRIPTING_API_ОБЗОР.md).

Официальное руководство: [Introduction to Entity Properties](https://learn.microsoft.com/en-us/minecraft/creator/documents/introductiontoentityproperties?view=minecraft-bedrock-stable).

## Особое внимание: события и значения по умолчанию

Некоторые поля ограничивают выражения сильнее, чем обычный код анимации. В документации Entity Properties описаны ограничения Molang-выражений, используемых при назначении свойств через событие и при вычислении значений по умолчанию. В таких местах могут быть недоступны произвольные query или присваивание переменных.

Поэтому:
- не предполагайте, что query из анимации сработает в обработчике события;
- читайте документацию конкретного поля, а не только общий справочник Molang;
- при ограничениях переносите вычисление в подходящее место, если это соответствует задаче;
- не объявляйте пример универсальным, если он проверен только в одном контексте.

## Типовые ошибки

| Симптом | Возможная причина | Что проверить |
|---|---|---|
| Выражение возвращает 0 | Неинициализированная переменная, ошибка вычисления или недоступные данные | Content Log, имя, доступность query и тип результата. |
| Query не распознаётся | Опечатка, неподходящая версия или контекст | Сигнатуру query и страницу конкретного поля. |
| Значение теряется после перезагрузки | Использована Molang variable вместо сохраняемого механизма состояния | Нужна ли Entity Property или иное хранилище. |
| Выражение работает в анимации, но не в событии | Контекст события ограничивает операции | Документацию поля и ограничения выражений в событиях. |
| Текстура или геометрия не выбирается | Ошибка ссылки или типа результата | Регистрацию ресурса, массив вариантов и ожидаемый тип. |

## Практический чек-лист

- [ ] Зафиксируйте поле JSON, где используется выражение.
- [ ] Подтвердите, что поле принимает Molang.
- [ ] Проверьте query и её аргументы в актуальном справочнике.
- [ ] Инициализируйте переменные до чтения.
- [ ] Убедитесь, что тип и диапазон результата подходят полю.
- [ ] Проверьте Content Log и поведение в целевой версии игры.
- [ ] Если пример зависит от Preview, явно пометьте это.
