# Структура Behavior Pack и Resource Pack

> Статус: обзор распространённых типов файлов. Полный список зависит от возможностей, которые использует проект, и версии Minecraft.

## Главный принцип

Minecraft распознаёт содержимое Add-On по типу файла, имени каталога и расположению. Наличие файла в произвольной папке не гарантирует, что игра его загрузит. В каждом пакете должен быть корректный `manifest.json`; остальные каталоги добавляются по мере необходимости.

Официальные источники:
- [Полный список содержимого пакетов](https://learn.microsoft.com/en-us/minecraft/creator/documents/comprehensivepackcontents?view=minecraft-bedrock-stable)
- [Создание нового типа сущности](https://learn.microsoft.com/en-us/minecraft/creator/documents/introductiontoaddentity?view=minecraft-bedrock-stable)

## Behavior Pack (BP)

BP содержит игровые правила и данные поведения. В зависимости от проекта здесь могут находиться:

| Путь | Назначение |
|---|---|
| `manifest.json` | Обязательное описание пакета и его модулей |
| `entities/` | Определения поведения сущностей |
| `items/` | Определения предметов |
| `blocks/` | Определения пользовательских блоков |
| `functions/` | Функции команд `.mcfunction` |
| `loot_tables/` | Таблицы добычи |
| `recipes/` | Рецепты |
| `spawn_rules/` | Правила появления сущностей |
| `trading/` | Данные торговли, если используются |
| `animation_controllers/` | Контроллеры анимаций поведения |
| `animations/` | Анимации, используемые пакетом |
| `features/`, `feature_rules/` | Данные генерации мира, если используются |
| `structures/` | Структуры в поддерживаемом формате |
| `texts/` | Локализуемые строки и языковые файлы |

## Resource Pack (RP)

RP отвечает преимущественно за визуальные и аудиоресурсы. В нём могут использоваться:

| Путь | Назначение |
|---|---|
| `manifest.json` | Обязательное описание пакета |
| `entity/` | Клиентские определения сущностей и связи с ресурсами |
| `textures/` | Текстуры и атласы |
| `models/` | Геометрия моделей, если используется |
| `animations/` | Анимации визуальной стороны |
| `animation_controllers/` | Контроллеры визуальных состояний |
| `render_controllers/` | Правила отрисовки |
| `particles/` | Определения частиц |
| `sounds/`, `sounds.json` | Звуковые ресурсы и их описания |
| `texts/` | Локализация отображаемых названий |
| `materials/` | Материалы в поддерживаемых сценариях |

Не создавайте пустые каталоги «на всякий случай»: добавляйте только те, которые нужны вашему контенту.

## Как связаны BP и RP

Для пользовательской сущности BP описывает поведение, а RP описывает клиентское представление: геометрию, текстуры, анимации и рендеринг. Чтобы сущность выглядела правильно, идентификаторы и ссылки между файлами должны совпадать. Для многих пользовательских сущностей нужны оба пакета.

## Минимальный порядок сборки

1. Создайте отдельные каталоги BP и RP.
2. Добавьте в каждый необходимый `manifest.json`.
3. Опишите поведение в BP.
4. Добавьте клиентское определение и ресурсы в RP.
5. Проверьте UUID, версии модулей и зависимости.
6. Подключите пакеты к тестовому миру.
7. Смотрите Content Log после каждого небольшого изменения.

## Типичные ошибки

- Неправильное имя каталога или расширение файла.
- Файл создан в RP, хотя его ожидает BP, или наоборот.
- Несогласованные идентификаторы.
- Сломанный JSON: лишняя запятая, кавычка или скобка.
- Неактуальный `format_version` или использование функции, не поддерживаемой целевой версией.
- Пакет не включён в мир или зависимость между пакетами не объявлена корректно.
