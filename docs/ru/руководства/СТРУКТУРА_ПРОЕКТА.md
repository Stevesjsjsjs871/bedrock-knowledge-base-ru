# Структура проекта Add-On

> Статус: `editorial-explanation`. Состав папок зависит от типов содержимого, инструментов и версии.

## Пример организации
```text
my_addon/
├── behavior_pack/
│   ├── manifest.json
│   ├── entities/
│   ├── items/
│   ├── blocks/
│   ├── recipes/
│   ├── spawn_rules/
│   ├── scripts/
│   └── texts/
└── resource_pack/
    ├── manifest.json
    ├── entity/
    ├── models/
    ├── animations/
    ├── animation_controllers/
    ├── render_controllers/
    ├── textures/
    └── texts/
```

Это ориентир, а не требование создавать все каталоги в каждом проекте. Добавляйте только нужные типы контента.

## Где что хранить
| Каталог | Назначение |
|---|---|
| `entities/` в BP | Определения поведения сущностей |
| `items/` в BP | Определения предметов, когда они нужны проекту |
| `blocks/` в BP | Определения блоков |
| `recipes/` в BP | Рецепты крафта и другие поддерживаемые рецепты |
| `spawn_rules/` в BP | Условия естественного появления сущностей |
| `scripts/` в BP | Скрипты, если проект использует Scripting API |
| `entity/` в RP | Клиентские определения сущностей |
| `models/` в RP | Геометрия моделей |
| `animations/` в RP | Описания анимаций |
| `animation_controllers/` в RP | Логика состояний и переходов анимаций |
| `render_controllers/` в RP | Правила отображения сущностей |
| `textures/` в RP | Изображения для визуальных ресурсов |
| `texts/` | Локализационные строки в поддерживаемом формате |

## Рекомендации по именованию
- Выберите namespace, который с высокой вероятностью уникален.
- Не используйте `minecraft` для собственных идентификаторов.
- Делайте имена файлов и каталогов предсказуемыми и последовательными.
- Не меняйте идентификатор без проверки всех ссылок на него.
