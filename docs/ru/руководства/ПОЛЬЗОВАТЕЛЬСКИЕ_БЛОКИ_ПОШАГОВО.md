# Пользовательский блок: путь от JSON до тестирования

**Статус:** editorial-explanation · поля зависят от формата блока и версии Minecraft.

Это практическое дополнение к [обзору пользовательских блоков](ПОЛЬЗОВАТЕЛЬСКИЕ_БЛОКИ.md). Оно связывает определение блока, состояния, permutations, текстуру, лут и проверку в один рабочий процесс.

Официальные источники:
- [Block JSON Documentation](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/?view=minecraft-bedrock-stable)
- [Building with Custom Components](https://learn.microsoft.com/en-us/minecraft/creator/documents/scripting/components-tutorial?view=minecraft-bedrock-stable)
- [Comprehensive Add-On Pack Contents](https://learn.microsoft.com/en-us/minecraft/creator/documents/comprehensivepackcontents?view=minecraft-bedrock-stable)

## Слои пользовательского блока

1. **Определение блока в Behavior Pack.** Идентификатор, поддерживаемые компоненты, состояния и условные permutations.
2. **Визуальные ресурсы в Resource Pack.** Текстуры, записи атласа и при необходимости геометрия или материалы.
3. **Ресурсы отображаемого имени.** Для локализованного имени добавьте соответствующий ключ в языковые файлы.
4. **Поведение при разрушении и взаимодействии.** Лут, допустимые места размещения и дополнительные механики.
5. **Тестирование.** Загрузка пакетов, размещение, разрушение, смена состояний и диагностика.

Файлы должны быть связаны правильными идентификаторами и путями. Само наличие файла не подключает его автоматически.

## Шаг 1. Начните с минимального блока

Выберите уникальный namespace, например sample, и идентификатор sample:glowing_stone. До добавления сложной логики убедитесь, что блок загружается и размещается в тестовом мире.

Не копируйте формат версии из старого примера вслепую. Сверьте format_version и набор компонентов с актуальной Block Reference.

## Шаг 2. Подключите текстуру

Проверьте цепочку от текстурного файла до регистрации и использования в блоке. Имя файла, ключ в атласе и ссылка в определении должны согласовываться. Ошибка визуальной ссылки не всегда означает, что само определение блока неверно.

На первом тесте используйте одну текстуру и минимальную визуальную конфигурацию.

## Шаг 3. Добавляйте состояния только при необходимости

Состояние полезно, если один блок должен иметь несколько вариантов: например, степень роста или включённое/выключенное состояние. Состояние должно быть объявлено, а затем использоваться с тем же именем и допустимым типом значения.

Состояния увеличивают число комбинаций, которые нужно проверять.

## Шаг 4. Используйте permutations для условных вариантов

Permutation задаёт альтернативный набор поддерживаемых компонентов при выполнении условия. Условие может ссылаться на объявленное состояние блока, но синтаксис и допустимые компоненты проверяйте по актуальной схеме.

Добавляйте по одному условию. Проверьте и вариант, когда условие истинно, и вариант, когда оно ложно.

## Шаг 5. Настройте разрушение и лут

Проверьте, какой механизм задаёт добычу блока, и подключите существующую таблицу лута, если она нужна. Не путайте выпадение предмета с исчезновением блока или с возможностью его разрушить: это связанные, но отдельные аспекты.

## Шаг 6. Добавляйте пользовательские компоненты последними

Если встроенных компонентов недостаточно, пользовательский компонент может связать блок с Script API. Это добавляет требования к регистрации, версии API и согласованию идентификатора между JSON и кодом.

Сначала убедитесь, что базовый блок работает без скрипта. Затем добавьте минимальный обработчик и тестируйте одно событие за раз. Формат регистрации custom components менялся между версиями, поэтому сверяйте актуальное руководство.

## Таблица диагностики

| Симптом | Проверка |
|---|---|
| Блок не появляется в игре | Активность BP/RP, JSON, идентификатор и Content Log. |
| Блок невидим или с неправильной текстурой | Текстурный файл, atlas, ключи и визуальные ссылки. |
| Состояние не меняется | Объявление состояния, точное имя, тип значения и логика изменения. |
| Permutation не применяется | Выражение условия и поддержка компонентов. |
| Не выпадает предмет | Ссылка на loot table, тип добычи и условия. |
| Не вызывается пользовательский код | Регистрация компонента, версия Script API, ID и поддерживаемый обработчик. |

## Минимальная матрица тестов

- [ ] Пакет включён, ошибок загрузки нет.
- [ ] Блок размещается и сохраняется после перезахода в мир.
- [ ] Текстура и отображаемое имя корректны.
- [ ] Все объявленные состояния проверены.
- [ ] Для каждой permutation проверены истинный и ложный сценарии.
- [ ] Разрушение и дроп проверены отдельно.
- [ ] Пользовательские компоненты проверены после базовых сценариев.
- [ ] Поведение сверено с целевой версией Minecraft.
