# Проверка JSON и схем Minecraft Bedrock

## Зачем нужна проверка схемы

JSON может быть синтаксически корректным, но при этом не соответствовать ожидаемой схеме Minecraft. Например, ключ может быть написан неверно, иметь неправильный тип или находиться не на том уровне вложенности.

Поэтому проверка состоит из нескольких уровней:

1. **Синтаксис JSON** — файл можно разобрать как JSON.
2. **Структура** — обязательные поля и вложенность соответствуют формату.
3. **Семантика** — ID, ссылки и значения имеют смысл для игры.
4. **Совместимость** — нужная возможность поддерживается целевой версией и выбранным треком.
5. **Проверка в игре** — пакет действительно загружается и работает ожидаемым образом.

Успех на одном уровне не гарантирует успех на остальных.

## Рекомендуемый процесс

1. Сначала проверьте файл обычным JSON-парсером.
2. Затем используйте подходящую схему или инструмент редактора для конкретного типа файла.
3. Сверьте неизвестные поля с официальным справочником.
4. Проверьте идентификаторы и пути к связанным ресурсам.
5. Запустите игру с включённым пакетом и изучите Content Log.
6. Проверяйте изменения постепенно, чтобы было понятно, какая правка вызвала проблему.

## Не используйте одну схему для всего

Entity JSON, Item JSON, Block JSON, Recipe JSON и другие форматы имеют разные структуры. Схема для одного вида контента не является универсальным валидатором всего Add-On.

Даже подходящая схема может относиться к другой версии. Перед тем как доверять её результату, проверьте, на какой версии игры и каком формате она основана.

## Типичные ошибки

- Лишняя запятая или незакрытая скобка.
- Строка вместо числа или булева значения.
- Неверное имя компонента.
- Поле в неправильном месте.
- Несуществующий идентификатор или путь.
- Preview-поле в проекте, рассчитанном на Stable.
- Устаревшая схема, которая не знает о новом поле или допускает уже недействительное.
