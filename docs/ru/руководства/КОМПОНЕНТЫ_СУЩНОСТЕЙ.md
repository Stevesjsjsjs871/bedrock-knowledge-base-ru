# Компоненты сущностей

Компонент — именованный объект данных, который задаёт характеристику или поведение сущности. Например, компонент здоровья задаёт параметры здоровья, а компонент поведения описывает одну из целей AI. Идентификаторы компонентов не переводятся.

## Перед тем как менять компонент
1. Уточните точную версию Bedrock и используемый трек — Stable или Preview.
2. Откройте соответствующую страницу [Entity Reference Stable](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/entityreference/?view=minecraft-bedrock-stable) или документацию нужного Preview.
3. Сверьте имя компонента, поля, типы, значения по умолчанию и ограничения версии.
4. Проверьте, должен ли компонент находиться в базовом определении или в component group.
5. Подготовьте минимальный тест и запишите ожидаемый результат.

## Компоненты и группы
- Компоненты в базовом разделе действуют в исходном состоянии.
- Component groups описывают наборы компонентов для отдельных состояний.
- События могут добавлять и удалять группы, меняя набор компонентов сущности.

## Как читать страницу компонента
Запишите назначение, имя, поля и типы, значения по умолчанию, ограничения версии, минимальный JSON-пример, типичные ошибки и первоисточник. Не считайте пример проверенным в игре только потому, что он проходит JSON-проверку.

Пример формы данных:
```json
{
  "minecraft:health": { "value": 20, "max": 20 }
}
```
Это схематичный пример структуры, а не гарантия полноты компонента для любой версии. Проверяйте доступность и ограничения компонента для нужной версии.

## Проверка после изменения
1. Проверьте JSON и схему.
2. Проверьте связанные component groups, события и идентификаторы.
3. Запустите тест в отдельном мире.
4. Изучите Content Log и проверьте связанные поведения.
5. Зафиксируйте точную версию, платформу, шаги и результат.
