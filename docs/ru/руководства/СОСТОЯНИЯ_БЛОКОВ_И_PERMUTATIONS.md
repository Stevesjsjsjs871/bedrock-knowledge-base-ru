# Состояния блоков и permutations

> Статус: архитектурный обзор с упрощённым примером. Сверяйте доступные компоненты и требования format_version с официальным Block Reference для целевой версии.

## Три связанные части

- **States** — именованные значения состояния блока, например стадия роста или ориентация.
- **Permutations** — условные варианты компонентов, которые применяются, когда выражение-условие истинно.
- **Components** — свойства блока, например геометрия, добыча, прочность и другие поддерживаемые характеристики.

Состояние само по себе не меняет внешний вид и поведение автоматически. Его значение должно быть связано с логикой, permutation, визуальным ресурсом или скриптом, который использует это состояние.

## Упрощённый пример

Следующий фрагмент показывает идею: у блока есть числовое состояние возраста, а условие выбирает набор компонентов для зрелого блока. Это учебный фрагмент, не полный файл блока; перед использованием проверьте актуальный формат и нужные компоненты.

~~~json
{
  "format_version": "1.21.10",
  "minecraft:block": {
    "description": {
      "identifier": "sample:crop",
      "states": {
        "sample:age": [0, 1, 2, 3]
      }
    },
    "permutations": [
      {
        "condition": "query.block_state('sample:age') == 3",
        "components": {
          "minecraft:loot": "loot_tables/sample_crop.json"
        }
      }
    ],
    "components": {
      "minecraft:loot": "loot_tables/sample_seed.json"
    }
  }
}
~~~

В примере идентификатор состояния и условие должны совпадать. Путь к таблице лута должен вести к существующему ресурсу в пакете. Если пример адаптируется к другой версии, перепроверьте format_version и совместимость каждого поля.

## Проектирование состояний

Перед созданием состояний решите:

1. Какое состояние нужно хранить: число, логический вариант или перечисление допустимых значений?
2. Какие системы меняют значение?
3. Какие permutations зависят от значения?
4. Как состояние отображается визуально?
5. Как оно влияет на добычу, столкновения или взаимодействие?
6. Что происходит при размещении, разрушении и обновлении блока?

Используйте минимально необходимое число состояний. Если две переменные всегда меняются вместе и не несут независимого смысла, пересмотрите модель, чтобы не создавать лишние комбинации.

## Условия и порядок проверки

Условия permutations могут опираться на поддерживаемые выражения, включая Molang в соответствующих контекстах. Не переносите произвольный Molang-запрос в контекст блока без проверки его доступности.

Если несколько условий могут быть истинными, изучите правила применения permutations в актуальной документации. Не предполагайте, что порядок массива заменяет правила приоритета или объединения компонентов.

## Типичные ошибки

- Состояние объявлено, но никогда не изменяется.
- Условие использует другое имя состояния.
- Значение не входит в объявленный список.
- В permutation указан несуществующий компонент.
- Путь к таблице лута неверен.
- Ожидается, что изменение состояния автоматически переключит геометрию без соответствующей визуальной настройки.
- Пример скопирован из другой версии без проверки format_version.

## Тестирование

1. Сначала создайте простой блок без permutations.
2. Добавьте одно состояние.
3. Проверьте, что состояние распознаётся игрой.
4. Добавьте одну permutation с простым условием.
5. Проверьте каждое допустимое значение состояния.
6. Добавьте визуальные и игровые различия по одному.
7. Проверьте Content Log.
