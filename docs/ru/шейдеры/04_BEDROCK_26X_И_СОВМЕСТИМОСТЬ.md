# Шейдеры Minecraft Bedrock 26.x: совместимость и новые схемы

## Сначала разобраться с нумерацией

Начиная с 2026 года Minecraft использует нумерацию релизов по году: публичные версии Bedrock начинаются с `26` (26.0, 26.20 и т. п.). При этом в документации для Creator API и JSON-схем могут встречаться внутренние номера вида `1.26.xx`. Не смешивайте версию приложения и версию схемы ресурса.

- [Официальный changelog Bedrock 26.0](https://feedback.minecraft.net/hc/en-us/articles/43274629736717-Minecraft-Bedrock-Edition-26-0-Changelog)
- [Creator update notes 1.26.0](https://learn.microsoft.com/en-us/minecraft/creator/documents/update1.26.0?view=minecraft-bedrock-stable)

## Проверять нужно не только номер игры

Для каждого пака заведите четыре независимых поля:

1. **Версия игры** — например 26.0 или 26.20.
2. **Версия схемы JSON** — например `format_version` конкретного lighting/water/atmospherics JSON.
3. **Минимальная версия в manifest** — `min_engine_version`.
4. **Поддерживаемый графический режим и устройство** — Vibrant Visuals, RTX либо обычный рендеринг, плюс платформа/GPU.

Если автор указывает «26+», это полезная подсказка, но недостаточная гарантия: разные выпуски 26.x могут менять графические схемы, поля или поведение. Смотрите release notes и тестируйте каждый релиз отдельно.

## Пример подтверждённого изменения в 26.20

Официальный changelog 26.20 сообщает о новой версии схемы atmospheric scattering с `format_version` `1.26.20`, а также о новых обязательных полях `minecraft:atmosphere_settings` и `minecraft:atmosphere_settings/description`. В том же выпуске добавлены изменения для конфигурации воды. Поэтому JSON, написанный под более раннюю схему, следует проверять по документации соответствующего выпуска.

Источник: [Bedrock 26.20 Changelog](https://feedback.minecraft.net/hc/en-us/articles/45400537384333-Minecraft-Bedrock-Edition-26-20-Changelog).

## Рекомендуемая политика версий

- Для первого релиза пака зафиксируйте минимальную версию, на которой реально проверяли его структуру и графический результат.
- Для каждого обновления игры проверяйте JSON-схемы и официальные changelog.
- Не повышайте `min_engine_version` механически без понимания причины.
- Не понижайте `min_engine_version` только ради импорта: старый движок может игнорировать поля или не поддерживать формат.
- Ведите отдельные файлы/ветки конфигураций, если одна схема не совместима со всеми поддерживаемыми версиями.
- Если проверка выполнена только на 26.20, не маркируйте пак как «26.x проверено» без тестов на остальных заявленных версиях.
