# Матрица изменений графики Bedrock 26.x

## Как читать таблицу

Bedrock использует новую нумерацию релизов с 2026 года: номер 26.x относится к версии игры. При этом format_version в графическом JSON — версия схемы конкретного файла. Например, в 26.20 для некоторых конфигураций применена схема 1.26.20.

| Версия / рубеж | Подтверждённое изменение | Что делать авторам паков |
|---|---|---|
| 26.0 | Переход к новой годовой нумерации релизов; сама нумерация не означает автоматическую смену схем всех JSON | Записывать полную версию игры и проверять schema version каждого типа файла отдельно |
| 26.0, настройки освещения | В документации схемы освещения 1.26.0 отмечена поддержка key framing для параметров неба и ambient | Проверить ключевые значения и сравнить время суток; не переносить правило на другие схемы без подтверждения |
| 26.20, атмосфера | Новая версия схемы атмосферного рассеяния 1.26.20; minecraft:atmosphere_settings и minecraft:atmosphere_settings/description обязательны | Проверить структуру файла, обязательные поля и идентификатор |
| 26.20, вода | Новая версия схемы воды 1.26.20; minecraft:water_settings и minecraft:water_settings/description обязательны | Мигрировать только конфигурацию воды, затем проверить загрузку и видимый эффект |
| 26.20, Vibrant Visuals | В changelog отмечены графические исправления и поддержка Vibrant Visuals для дополнительных ресурсов | Проверять изменения по релизу; не приписывать их всем предыдущим версиям |

Таблица включает только изменения, подтверждённые перечисленными официальными источниками на момент подготовки статьи. Она не является исчерпывающим списком всех графических изменений 26.x.

## Процедура обновления пакета

1. Сохраните рабочую копию и запишите текущую версию Bedrock.
2. Проверьте официальный changelog для целевого выпуска.
3. Найдите схему каждого используемого файла: lighting, atmospherics, water, color grading, texture sets и per-biome mapping.
4. Определите, изменились ли обязательные поля, типы или допустимые значения.
5. Не заменяйте format_version во всех файлах одной операцией.
6. Выполняйте миграцию по одному файлу и сохраняйте diff.
7. Проверяйте JSON синтаксически, а затем в игре.
8. Записывайте ошибки Content Log и результат визуальной проверки.
9. При поддержке нескольких версий указывайте диапазон проверенных версий, а не просто «26+».

## Минимальный журнал совместимости

| Поле | Что записать |
|---|---|
| Игра | Полная версия и канал (Stable/Preview) |
| Платформа | Windows, Android, iOS или другая |
| Устройство / GPU | Модель и графическое оборудование, если известно |
| Режим | Vibrant Visuals, RTX или обычный рендеринг |
| Пак | Версия, автор и ссылка на исходный релиз |
| Файлы | Какие конфигурации и Texture Sets изменены |
| Импорт | Успех/ошибка |
| Content Log | Ошибки и предупреждения |
| Видимый результат | Что конкретно изменилось |
| Повторяемость | Повторено ли после перезапуска и на чистом профиле |
